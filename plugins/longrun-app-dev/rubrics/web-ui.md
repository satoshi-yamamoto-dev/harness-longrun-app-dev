# Web UI detail rubric

Use uiScores with designQuality, originality, craft and functionality, each 0–10.
Design quality and originality deserve focused observation; this does not relax the
other thresholds. Each subscore must individually pass. The first three use the
configured visualDesign threshold, and UI functionality uses functionality's threshold.

| Criterion | Below 4 | 4–7 | 8–10 |
| --- | --- | --- | --- |
| designQuality | No readable hierarchy or coherent structure | Legible but mixed visual decisions and weak hierarchy | Type, spacing, color and layout form a coherent experience |
| originality | Stock/demo appearance with no product decisions | Conventional template with limited adaptation | Deliberate product-specific composition and interaction decisions |
| craft | Clipping, overlap, illegibility or broken focus | Visible alignment, contrast, spacing or mobile defects | Consistent detail, responsive layout, visible focus and clear state feedback |
| functionality | Primary control is disconnected or misleading | Core navigation works but important interactions fail | Users can understand and complete required tasks; controls reflect real state |

Inspect actual screenshots at desktop and narrow viewport sizes and operate the UI.
Record what was inspected in every rationale. Generic styling alone is not evidence
of high originality. Beautiful styling cannot compensate for an inoperative control.
Do not infer accessible behavior solely from a screenshot; inspect focus and labels.
